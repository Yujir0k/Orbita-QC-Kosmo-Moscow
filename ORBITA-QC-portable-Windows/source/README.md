# ОРБИТА.QC — исходный код

React 19, TypeScript strict, Vite 6. Новых production-зависимостей нет.

## Запуск и пересборка

```powershell
pnpm install --frozen-lockfile
pnpm data:sync
pnpm dev
pnpm test
pnpm build:portable
```

`data:sync` читает `../../quality_dataset/expanded_dataset`: 180 изделий, справочники, индекс 8 фото и **только** `events/source_deliveries.jsonl`. Скрипт создаёт `src/demo-data.json`, реальные изображения в `public/media/` и копии внешнего и ошибочного потоков в `public/demo/`. План контроля и проектные интеграционные профили хранятся отдельно в `src/config.json`. Старый набор из 12 изделий не импортируется повторно. Файлы `expected/*` и `interactions/scripted_actions.jsonl` не являются входом приложения.

`pnpm build:portable` выполняет строгую проверку типов, Vite-сборку и переносит `dist/` в `../site/`. Для обновления итогового архива из этой папки запустите `py -3 scripts/package-windows.py`: скрипт создаст `../../ORBITA-QC-workspaces-Windows.zip` с переносимым приложением и расширенным набором данных. Для запуска готовой версии используйте `../START.cmd`. При разработке сначала запустите API в другом терминале: `$env:ORBITA_PORT=5174; node ../server.mjs`, затем `pnpm dev`; Vite перенаправляет `/api` на порт 5174. Один `pnpm dev` без API покажет экран входа с ошибкой соединения.

## Работа демо

- При первом открытии приложение принимает внешний поток до первого сигнала или невозможности оценки для каждого проблемного изделия. Обычные изделия проходят автоматически. Последующие внешние операции этих изделий остаются в ожидании действия роли.
- Администратор → «Поток событий» → «Сценарии и воспроизведение» управляет загрузкой встроенного набора, паузой, следующим шагом, продолжением, сбросом и импортом JSON/JSONL. «Качество данных» отдельно показывает результаты приёма. «Проверить ошибочный поток» берёт из `ingest_stream.jsonl` только намеренно ошибочные доставки.
- Контролёр открывает задачу и записывает решение. Мастер фиксирует работу с исполнителем и комментарием; в опорных сценариях соответствующее учебное фото прикрепляется автоматически. Технолог записывает гипотезу или заключение о допустимости. После работы мастера выпуск оформляет контролёр.
- При запуске сервер показывает пароли учебных ролей в своём окне. Для смены роли нужно выйти и войти под другой учётной записью. Критические действия проходят серверную проверку и защищённый журнал; `localStorage` остаётся кэшем представления. «Сбросить» возвращает исходное демосостояние в браузере.
- Фото представлены синтетическими учебными материалами. Фото ITEM-013 не заменяет отдельный ручной замер 5,12 мм. У ITEM-015 до действия мастера кадр отсутствует.
- Через `../START.cmd` доступен серверный обмен: администратор получает задание от ERP-эмулятора, отправляет результат и видит квитанцию. Для `ITEM-007` эмулятор возвращает временный отказ на первой попытке; сервер повторяет отправку. Состояние обмена сохраняется в `../data/integration-state.json`. Вкладка КОМПАС принимает JSON-структуру сборки из `integration-fixtures/assemblies.json`.
- Мастер → «Мобильные комплексы» выдаёт учебное задание, имитирует потерю связи и осмотр. Буфер и доставка результата сохраняются сервером; наблюдение появляется в истории изделия. Реальный робот не подключён; контракт расширения описан в `../MOBILEOPS_КОНТУР.md`.

## Границы реализации

Это локальная демонстрация. Серверный обмен работает с локальным ERP-эмулятором; адаптеры ERP, MES и серверный клиент CAD-адаптера проверены только на HTTP-стендах. Настройки и форматы приведены в `../ERP_АДАПТЕРЫ.md` и `../MES_КОМПАС_АДАПТЕРЫ.md`. Критические действия проверяются сервером и сохраняются в защищённом журнале; браузерное состояние остаётся учебной проекцией. Учебные пароли, локальный ключ и файловый журнал не заменяют корпоративное управление учётными записями, ключами и WORM-хранилище. Полное описание и демонстрация — в `../БЕЗОПАСНОСТЬ_И_АУДИТ.md`. Подключения к настоящим ERP/MES и SDK-процесс КОМПАС-3D не проверены.
